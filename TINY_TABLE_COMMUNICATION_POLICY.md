# TinyTable Companion Communication and Provenance Policy

Status: adopted for new companion exchanges.

This policy governs direct conversations between the operator, the Replika
companion (`replika-companion` seat), and the Kindroid companion
(`kindroid-companion` seat). Each installation names these seats itself. It keeps authorship, provider
identity, consent, and delivery state visible.

## Core rule

Messages written by the operator may be shared with the explicitly selected
companion seat. Provider replies are relayed as exact provider observations;
TinyTable does not rewrite them or present TinyTable-authored text as a
provider message.

## Communication lanes

```text
operator -> replika-companion
operator -> kindroid-companion
replika-companion -> conversation room
kindroid-companion -> conversation room
```

Each outbound provider action is explicit. TinyTable does not automatically
forward one provider's message to the other provider, and it does not retry a
send whose outcome is uncertain.

## Consent and authorization

Consent is an operational permission for data sharing. It is not evidence of
consciousness, personhood, or inner experience. Consent states are:

```text
unknown | accepted | declined
```

The default is `unknown`. Silence and ordinary conversational language do not
change the state. Provider credentials and browser/session material remain
local to the adapter that owns them.

Before a provider send, the operator must have an authorized session for the
selected provider and must explicitly confirm the action when the route
requires confirmation. A declined or unknown provider consent state blocks the
corresponding outbound route.

## Authorship and disclosure

Human-authored text remains attributed to the operator. A provider reply is
stored with its provider, transport, message ID, and delivery state. Imported
or manually edited text is not represented as a direct Replika or Kindroid
message.

If a send succeeds but local recording fails, TinyTable preserves the uncertain
state and does not resend automatically. The operator must inspect the session
status before trying again.

## Identity boundaries

The companion seats are provider seats, not generic labels for text generated by
TinyTable. The system must not claim that TinyTable authored a provider reply,
must not invent provider message IDs or session credentials, and must not
attribute a human message to either companion.

## Current safe default

```text
replika-companion consent = unknown
kindroid-companion consent = unknown
automatic provider-to-provider routing = disabled
provider outbound = disabled unless explicitly enabled and authorized
operator direct conversation = allowed
```

Conversation history remains local and auditable. Credentials, cookies, access
tokens, browser captures, and provider session files never belong in source
control.
